LIFEOS — YOUR PRIVATE LIFE MANAGEMENT APP

MASTER PRODUCT SPECIFICATION & AI DEVELOPMENT PROMPT

---

1. PRODUCT IDENTITY

App Name: LifeOS

Platform: Android

Product Type: Personal Life Management Application

Tagline:

«Capture your life. Organize your life. Understand your life.»

LifeOS is an all-in-one Android application designed to help users capture, organize, track, manage, understand, and preserve different aspects of their personal life from one private application.

LifeOS combines:

- Smart Notes
- AI Assistant
- Daily Task Manager
- Habit Tracker
- Expense Tracker
- Personal Diary
- Private Memories
- Photo Capture
- Video Capture
- Audio Memories
- Life Timeline
- Life Calendar
- Global Search
- Life Insights
- AI-powered personal analysis
- Backup and Restore

IMPORTANT: LifeOS is an Android application, NOT an operating system.

The word "OS" is part of the product name and represents the idea of having one central application for managing personal life.

---

2. CORE PRODUCT PHILOSOPHY

The most important principle of LifeOS is:

«"Your life. Your data."»

LifeOS should be:

- Private by design
- Offline-first
- Local-data-first
- Fast
- Modern
- Premium
- Personal
- AI-powered
- Easy to use
- Secure
- User-controlled

LifeOS should not feel like six or seven separate applications combined together.

It should feel like one connected personal application.

For example:

A note can become a task.

A task can become part of the day's timeline.

A photo can become a memory.

A memory can become part of a diary.

A habit can contribute to a productivity insight.

An expense can contribute to a financial insight.

A diary entry can contribute to a weekly or monthly life summary.

Everything should connect through:

- Date
- Time
- Tags
- Timeline
- Relationships
- LifeOS AI

LifeOS should be offline-first.

Primary user data should remain on the Android device by default.

Data includes:

- Notes
- Tasks
- Habits
- Expenses
- Diary
- Photos
- Videos
- Audio
- Captures
- Tags
- Timeline
- AI-generated content
- Settings

Core functionality should work without an internet connection wherever technically possible.

41. ANDROID PERMISSIONS

Do not request all permissions during first launch.

Request permissions only when the related feature is used.

Camera:

Ask when the user first uses Photo Capture.

Microphone:

Ask when the user first records Audio.

Notifications:

Ask when reminders are enabled.

Location:

Ask when the user chooses to attach location.

Photos/Media:

Use appropriate modern Android media APIs and request only necessary access.

Core principle:

«Minimum permission. Maximum control.»

59. MOST IMPORTANT PRODUCT RULES

The AI or developer working on LifeOS must follow these rules:

1. LifeOS is an Android application, not an operating system.
2. User data belongs to the user.
3. Local storage should be the default.
4. Offline functionality should be prioritized.
5. Do not upload personal data without user awareness and permission.
6. AI must respect permission-based data access.
7. AI should not silently modify important user data.
8. AI-generated diary entries must be reviewable.
9. AI-generated tasks must be reviewable.
10. Destructive actions require confirmation.
11. Important destructive actions may require typing DELETE.
12. Do not hardcode statistics or user information.
13. Use real database-backed data.
14. Keep features modular.
15. Keep UI fast and responsive.
16. Do not overload the Home screen.
17. Capture must be extremely fast.
18. Notes, Tasks, Habits, Expenses, Diary, Captures and Timeline should be interconnected.
19. Backup and export must be treated as important features.
20. Never make the user feel trapped inside LifeOS.
21. Privacy must be understandable to normal users.
22. Request Android permissions only when required.
23. Do not overuse glassmorphism.
24. Maintain excellent readability and accessibility.
25. The application should feel like one unified product rather than multiple mini-apps.
